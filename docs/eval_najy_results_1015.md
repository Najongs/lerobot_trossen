- **pad_hold(#60·#61)가 베이스 과회전을 줄이는지는 알 수 없다 [추정].** 넘친 프레임 세 개에서 #61 은 0054 +28° · 0101 +2° · 1029 +10° 로, 대조 #58(+43 · +16 · +24)보다 작다. 그러나 배포 중인 #27(+24 · +6 · +22)과 비교하면 0054 에서는 낫지 않다. 이어 학습한 #58 이 오히려 #27 보다 더 돈다. 오프라인 「끝 정지 0 → 95·100%」 는 **팔** 변위다. 시연 끝 프레임의 베이스 명령은 모든 모델이 이미 0.001~0.004 다(scoreSH 로그 t01 행).
- 예외는 #25(영상 드롭아웃)다. 넘친 프레임에서 +1~4° 로 멈추는데, 도달 순간(+11~28°)과 출발 회전은 다른 모델과 비슷하다. 다만 실기 출발에서 회전하며 전진해 충돌했다(0110). 학습 쪽 단서로만 둔다.
- **단위 확인**: 시연 t01 의 베이스 action 라벨은 state 와 같은 값이다(100 ep 전부 지연 0, 적분비 1.00). 시연 재생에서 라벨을 그대로 명령으로 보내면 시연과 −4.7° 차로 재현된다(README Base 절, task10). 그래서 **명령 누적과 시연 라벨은 같은 단위로 비교한다.**
- **작은 과회전(명령 +3~18°, #27 92~107° vs 시연 최대 89°)은 실재한다.** 다만 82° 도달 프레임에서 새로 예측해도 모든 모델이 1 s 에 +4~20°(대부분 +8~16°)를 더 낸다. 묵은 꼬리를 없애도 모델 자신의 「조금 더」 는 남는다. 그래서 「베이스만 짧게 재예측」 의 몫은 꼬리의 일부일 것이다 [추정]. #27 e30 ↔ e60 3 대 3 회차가 판정한다.
- 주의 — **늦은 청크는 정렬이 어긋난다.** 앞 청크(rp1·2)는 60 배수 틱에서 기록과 맞는다(오차 0.004~0.009, shift 0~±4). 넘친 청크는 맞지 않는다: 0054 rp4 는 shift 0 오차 0.062 · 최적 +28, 0101 rp3 은 최적 +26 에서 기록 +18° 를 +15° 로 재현한다(`GATESHIFT_1016.{py,log}`). 늦은 구간의 재예측이 60 배수 프레임에서 일어나지 않았을 수 있다. 원인은 미확인이다(프레임 누락·정렬·압축). 그래서 위 표의 rp 프레임은 「모델이 실제로 본 프레임」 이 아니라 「넘친 영역(>100°)의 프레임」 으로 읽는다. 모델끼리의 비교는 같은 프레임이라 유효하다. 관문(회차별 기록과 가장 가까운 모델)은 1045·1053 #27, 2143 #2, 0101 #29 만 맞았다.
