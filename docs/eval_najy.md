## 매 회차 공통 규칙

- 실행 로그 첫머리에 **`LEROBOT_TASK_ONEHOT=<i>/<K> installed`**, 첫 에피소드에 **`stage i/K active`** 가 보여야 한다.
  **없으면 ESC 로 즉시 중단** — 패치 없이 돈 런은 결과로 쓰지 않는다. (M1·M2·M3 만 해당. B* 는 원핫 없음)
- **exec 는 30** (B* 는 원래 chunk 가 100 — C 단계에서만 100 을 따로 본다).
- **팔 한 틱 이동 상한 0.1 rad** 가 기본으로 걸린다 (`MAX_REL`, 10/06 C-2 부터). 10/06 C-1 이전 회차와 같은 조건이 필요하면 `MAX_REL=none`. 요약의 「잘린 틱」 수를 기록한다.
- **리셋 구간에 터미널의 `POSE taskNN` 줄을 보며 자세를 맞춘다** (1초마다, `pose_guide.py`, 10/06~). `j1 +63→+90↑` = 현재 +63°, 목표 +90°, ↑ 는 각도를 키우라는 뜻(10° 이상 차이만 표시).
  「목표까지」 는 중앙값 자세까지의 거리라 「허용」(최근접 시작점 거리) 보다 크게 나온다 — 0.5 rad 아래면 대체로 허용 근처 [추정]. task08·10 은 중앙값이 참고용. 끄려면 `POSE_GUIDE=0`.
- 회차가 끝나면 **rerun 뷰어 창을 닫는다** — 열어 두면 스크립트가 요약 파일을 쓰기 전에 멈춘다(10/06 C-1).
- **시작 자세를 아래 표에 맞춘다** (리셋 구간에 리더암으로). 장면(튜브·비커 위치, 냉장고 문 상태)은 그 단계 학습 시연의
  첫 프레임과 같게 — 단계마다 기준 사진을 한 장 찍어 두고 매번 대조한다.
- 회차가 끝나면 바로 두 줄을 돌려 **시작 자세가 맞았는지**와 **움직임**을 남긴다 (로봇 안 움직임, 파일만 읽음):
  ```shell
  uv run --no-sync python scripts/eval_motion_stats.py kiroaiseoul/<학습 데이터셋> kiroaiseoul/eval_najy_<회차> --exec 30
  uv run --no-sync python scripts/eval_latency_stats.py <회차> --train kiroaiseoul/<학습 데이터셋>
  ```
  `시작점 최근접` 이 표의 「허용」 이하인 에피소드만 그 모델의 판정에 쓴다. 넘으면 「자세 불일치」 로 따로 적는다.
- 에피소드가 끝날 때마다 `~/eval_logs/eval_najy_results.csv` 에 한 줄: `run,episode,success(0/1),시작점최근접,비고`.
- 위험하면 비상정지 → 그 회차는 중단 기록. 스크립트 종료 코드가 0 이 아니면 요약 파일과 함께 남긴다.

## 순서

각 단계는 앞 단계가 끝나야 넘어간다. 에피소드 수는 첫 판단용 최소치다.

### A. 이미 있는 기록으로 — 로봇 안 움직임 (10분)

10/02 회차들에서 지연을 잰다:
```shell
uv run --no-sync python scripts/eval_latency_stats.py 1002_1150_m1_t04_e30 --train kiroaiseoul/task04_pour_liquid_from_tubes_to_beaker
uv run --no-sync python scripts/eval_latency_stats.py 1002_1422_base_t05_e30 1002_1438_base_t05_e30 --train kiroaiseoul/task05_tube_disposal
```
남길 것: 베이스 유효 지연(틱·ms)과 t63/t90, 정지 뒤 잔여 회전, **실기 팔 지연(틱) vs 학습 데이터 팔 지연(2틱)**, 추론 스파이크(ms).
베이스 계단이 적어 t63 이 안 나오면 B 의 `measure_base.py latency` 로 잰다.

### B. 정책 없이 재기 — 해석의 기준선

| 할 일 | 명령 | 남길 것 |
|---|---|---|
| B-1 녹화 주기 | 각 단계 **녹화 런**의 로그에서 `grep "Control loop rate" <녹화로그> \| grep phase=teleop \| tail -1` | `mean` Hz. 로그가 없으면 같은 조건으로 텔레옵 녹화를 30초 해서 잰다 |
| B-2 베이스 왕복 | `uv run --extra pi0 python scripts/measure_base.py rate` | 출력 전체 |
| B-3 베이스 응답 지연 | `uv run --extra pi0 python scripts/measure_base.py latency` ⚠️ **베이스가 움직인다** — 주변 1 m 비우기 | t63·t90 중앙값 |

> 베이스 속도 명령은 다음 명령까지 유지되므로 **(정책 런 루프 주기) ÷ (녹화 주기) 의 역수만큼 과회전**한다.
> ⚠️ `measure_base` 직후 바로 eval 을 띄우면 베이스 시리얼 포트를 못 잡은 사례가 있다 — 측정 프로세스가 끝났는지 확인하고 띄운다.

### C. task05 정지 원인 가르기 — 시작 자세를 표에 맞춰서

```shell
scripts/eval_najy.sh kiroaiseoul/act_task05_tube_disposal_60000 5 100 3    # B*, 원래 chunk 100 그대로
scripts/eval_najy.sh M1 5 30 3
scripts/eval_najy.sh M2 5 30 3
```
| 결과 | 뜻 | 다음 |
|---|---|---|
| 자세를 맞추니 M1·M2 가 움직이고 성공 | 원인은 시작 자세(장면) | D 로, 시작 자세 맞추기를 계속 |
| B* 만 되고 M1·M2 는 계속 정지 | 11단계 모델의 task05 문제 | 회차를 DGX 로 넘긴다(아래) — 실기 프레임을 모델에 다시 넣어 원인 분석 |
| 셋 다 정지 | 장면·조명 등 학습 때와 다른 것이 더 있다 | 기준 사진과 비교, 회차를 DGX 로 |

### D. 넓고 얕게 — M1 · exec 30 · 단계마다 3ep

A/B 비교를 깊게 하기 전에 11단계 각각에서 **된다 / 정지 / 엉뚱함** 을 먼저 분류한다.
베이스를 덜 쓰는 조작 단계부터, 이동 단계는 B 의 기준선이 있은 뒤에:
```shell
for s in 2 7 8 9 11; do scripts/eval_najy.sh M1 $s 30 3; done     # 조작 (task04 는 10/02 에 끝)
for s in 3 1 6 10; do scripts/eval_najy.sh M1 $s 30 3; done       # 이동 — task03(제자리 회전)이 가장 단순
```
이동 단계에서 볼 것: 회전량(정답 대비), 멈춘 뒤 제자리 유지(떨림/한 방향 표류), `basevel.csv` 의 명령·실측.

### E. 안 되는 단계만 비교

D 에서 정지·실패한 단계에 한해:
- 조작 → `scripts/eval_najy.sh M2 <s> 30 3`, 기존 전문가가 있으면 B* (task04 `act_task04_pour_liquid_from_tubes_to_beaker_60000`, task05 `act_task05_tube_disposal_60000`, 둘 다 16D·chunk 100)
- 이동 → `scripts/eval_najy.sh M3 <s> 30 3`, task06 은 B* `act_task06_pickup_beaker_and_move_to_refrigerator_14D_all_260923`
  (⚠️ `act_task10_..._14D_baseprogress_60k_fp32` 는 이름과 달리 16D 이고 베이스 칸 의미를 확인하지 못했다 — 기준선에서 뺀다)

### F. 정리

- 단계마다 승자(M1/M2/M3/B*)를 정한다. 갈리면 **단계마다 체크포인트를 나눠 쓴다** (M1·M2 는 둘 다 `/11`).
- 11단계 연속 실행은 `stage_runner`(PR #48, 미머지)가 리베이스·fps 21 타이머 재산정·원핫 전달을 갖춘 뒤.

## 문제가 생기면

| 증상 | 원인 후보 | 할 일 |
|---|---|---|
| `installed` 줄이 없음 | 패치 미반영 (`uv sync` 안 함, 다른 체크아웃) | 중단 → 「시작 전」 다시 |
| 첫 프레임에 `normalizer`·shape 에러 | 원핫 미적용 / 잘못된 모델 | 로그 첫 50줄 보내기 |
| `robot state is N wide` | `include_velocity` 등 관측 옵션이 켜짐 | 기본 설정으로 |
| 시작 후 팔이 거의 정지, 30틱마다만 움찔 | 시작 자세·장면이 학습과 다름 / 모델 | `시작점 최근접` 확인 → 「허용」 넘으면 자세부터. 맞는데도 정지면 C 의 표 |
| 베이스가 과하게 돈다 | 루프 주기 < 녹화 주기 | 요약의 `mean` Hz 와 B-1 비교 |
| 팔이 청크 경계마다 튄다 | 이음매 | `FIRED` 수 기록 |
| 베이스 통신 전부 실패 | 다른 프로세스(`measure_base` 등)가 포트를 잡음 | 그 프로세스 종료 후 재실행 |
| 끝났는데 요약(`.summary.txt`)이 안 나옴 | rerun 뷰어가 로그 파이프를 잡고 있음 | rerun 창 닫기 (Ctrl-C 하면 요약이 안 남는다) |
| `FileExistsError` | 같은 repo_id 재사용 | 스크립트는 분 단위 이름 — 1분 기다리고 재실행 |
