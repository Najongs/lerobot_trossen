# 정책 선정 — ACT 냐 VLA 기반이냐 · 같은 조건 맞대기 (2026-10-09, DGX_1 세션 · 사용자 합의 초안)

> **질문 하나**: 11단계 실기에서 정책을 **ACT 로 갈지, VLA 기반(SmolVLA)으로 갈지** — 정확히는 「지금 권장 배포 스택(모델 + 러너 설정) 둘 중 어느 쪽에 투자할지」 를 t05·t04·t03 실기로 가르는 **선별**이다. 고른 뒤 나머지 단계·체인 확인은 기존 관문(najy_plan_1008 G0→G1)대로. 판정은 오프라인 지표가 아니라 **실기 사람 판정**(사용자 10/09: 「측정 도구는 어쩔 수 없어 — 실전 Eval 로」).
> 이 문서는 설계·굽는 순서·실기 회차만 적는다(판정은 사용자가 실기 결과로). 결과는 `eval_najy_results_<MMDD>.md`, 누적은 [`eval_scoreboard.md`](eval_scoreboard.md), 학습 큐 정본은 sim `docs/multi_server_setup.md` 「GPU 송수신 루프」.
> 서버 이름: 이 레포·sim 문서의 **1호기 = DGX1**(`kiro-dgx1`) · 2호기 = sandia. (VLA_research 레포에서는 같은 DGX1 을 「3호기」 라 부른다 — 수치를 옮길 때 바꿔 읽는다.)

## 0. 왜 지금, 왜 이 설계 — 근거 요약
| 사실 | 근거 | 이 설계에 주는 것 |
|---|---|---|
| ACT 는 원핫을 거의 안 쓴다 — 실기 프레임에서 원핫 4↔5 교환 청크 차이 0.064 rad vs 카메라 교환 0.199. 1054: t05 자리에 원핫 5 를 줬는데 t04 붓기. 홀드아웃 10경계 중 9곳에서 원핫이 단계를 안 고른다 | 1006:94-113 · 1006:42 · sim §89 | 「다른 태스크를 초기 비전으로만 인식」 은 측정된 사실 |
| 원인은 **데이터 구조** — 데이터 안에서는 영상·state 가 단계를 다 정해 원핫이 잉여 | sim §89.2 | 모달리티를 바꿔도 같은 지름길이 생길 수 있다 → **「VLA 면 조건을 쓴다」 는 가설이 아니라 측정 대상** |
| 언어 조건 VLA 도 같은 증상을 냈다 — VLA-Adapter(LIBERO, VLM 에서 처음부터)는 lr 2e-4 에서 8런 중 7런이 지시문을 무시하고 시작 자세로 대상을 골랐다. 고친 것은 언어가 아니라 **낮은 lr**(5e-5, 접지 1/8 → 8/8) | VLA_research `01_설계.md` §8.10 · `metrics_h8b.txt` · 노하우대장 V-N-010 | VLA 쪽도 레시피가 결과를 가른다. 원핫 vs 언어 직접 비교는 어디에도 없다 |
| 지금까지의 ACT vs SmolVLA 비교는 **판정 불가** — 「ACT ≥ SmolVLA」(§74)는 오프라인 MAE, 「언어 변형 기각」(§94.11)은 §94.17 이 「선택을 못 잰다」 고 스스로 인정한 gt-Δ 지표, SmolVLA 는 시드 1·GIST 없음·청크 50·bf16, ACT 후보는 GIST·청크 100·fp32 | sim §74 · §94.11 · §94.17 | **데이터·분할·배치·증강을 맞춘 한 쌍**을 새로 굽는다 |
| GIST(같은 11단계를 다른 현장에서 찍은 16셋)를 **가중치 고정 30%** 로 섞으면 우리 홀드아웃은 유지, 다른 현장 출발 3/10 → 7~8/10 (ACT 15K, 두 시드). 「섞으면 나빠진다」(§65·66)는 **SmolVLA 사전학습·프레임 비례 혼합**의 희석 결과였다 | sim §94.38.1 · §66.1 | 두 팔 모두 같은 `gist30` 혼합 — 「다양한 데이터에 VLA 가 더 강한가」 도 같이 본다 |
| 실기 실패의 큰 몫은 **출발**(시연 시작 2~2.7 s 기다림 · 시작 장면이 「한 점」 · 그리퍼 state 복사) | HANDOFF_najy_1009 §2 · 1008 | 판정에 출발 실패를 따로 센다(모델 탓/실행 층 탓 구분) |

- 판정 제외(장면·자세 불일치·장비)는 **이유와 수치**(자세 오차 rad · 루프 Hz 등)를 같이 적는다 — 제외 여부를 결과를 본 뒤 정하지 않으려고.
- SmolVLA 출발 실패가 몰려 `long` 을 덧돌리면 보조 기록으로만 둔다(같은 조건 비교가 아니다).

## 4. 판정 — 사용자가 실기 결과를 보고 정한다 (사용자 10/09: 「판정 규칙은 내가 실제 Eval 돌려서 정한다」)
- 미리 정한 문턱은 두지 않는다. DGX 는 회차 기록을 모아 **모델별 성공 수(A·B 따로) · 실패 분류(`출발 못함` · `다른 단계 동작` · `그리퍼` · `중간 정지`) · 출발 s · 루프 Hz** 를 한 표로 정리해 판단을 돕는다.
- **모델은 섞지 않는다**(사용자 10/09) — 고른 하나로 11단계 전부를 간다. 그래서 이동 단계 t03(M5)도 같은 표에 넣는다.
- 읽는 한계(참고): 모델당 십여 회는 큰 차이만 가른다 — 예를 들어 두 모델의 실제 성공률이 같아도 12회씩이면 성공 수가 4 이상 벌어질 확률이 한쪽에 약 6~8% [이항분포 계산]. 「70% 달성」 판정(B 열 n≥10)과는 별개다.

## 5. 고른 뒤
- **ACT**: 지금 계획(najy_plan_1008 G0→G1) 그대로. 조건 무시는 레시피·데이터 쪽 레버로(드롭아웃·경계 데이터·재수집 복구 시연).
- **SmolVLA**: 나머지 단계로 확장. 이동 단계도 같은 모델로 간다.
- 어느 쪽이든 결과는 scoreboard 에 새 열 둘(`act gist30 60K s1000` · `smolvla gist30 60K s1000`)로 남긴다.

## 6. 알려진 차이 · 하지 않는 것
- **청크·실행이 다르다** — ACT 는 청크 100(시연 시작 기다림 2~2.7 s 를 한 청크에 담는 것이 출발의 열쇠였다, §94.31), SmolVLA 는 사전학습 청크 50 + 30 스텝마다 재계획. SmolVLA 를 청크 100 으로 바꾸는 것은 사전학습과 어긋나는 새 레시피라 이번엔 안 한다. 출발 실패가 SmolVLA 쪽에 몰리면 그때 `long`(commit 40) 1회를 덧붙인다.
- **ACT 는 시드 복권이 크다**(J10 10/10 vs A 8/10, GIST 홀드아웃 7 vs 3). 시드 1개 비교라 한 번 진 모델이 「항상 진다」 는 아니다.
- 하지 않는 것: 원핫을 더 세게 넣는 변형 · 120K 장기 학습 · 드롭아웃 0.5 · exec 5 (najy_plan_1008 §6). 서드파티(trossen 동작) 데이터 혼합은 변수가 늘어 이번 선정 밖.
- VLA_research 의 LR 노하우(warmup 500 · lr 5e-5)는 **VLM 에서 처음부터 학습** 조건 전용이라 `smolvla_base` 미세조정의 근거가 아니다 — SmolVLA 는 기본 레시피로 간다.

## 7. VLA 후보는 SmolVLA 하나 (사용자 10/09)
- **pi0 / pi0.5 제외** — lerobot 0.4.1 의 pi0 는 LoRA·부분 동결 옵션이 없어 전체 미세조정(약 3.5B)만 되고, openpi 기준 전체 미세조정은 GPU 1장에 > 70 GB(LoRA 는 > 22.5 GB)다. 학습 스크립트에 FSDP 도 없어 V100 32 GB·3090 24 GB 어디에도 그대로는 안 올라간다.
- **VLA-Adapter 제외** — 이식 비용이 크다(16D 인코딩·RLDS 변환·행동 헤드 재학습·로봇 PC 추론 서버 새로). VLA_research 의 결과는 참고로만.
