## 2. 코드 — 팔 켜고 끄기 시간 (사용자 「키고 끌 때 하나씩 오래 걸린다」)
- 원인: 팔마다 connect = staged 자세 2 s(blocking), disconnect = staged 2 s + sleep 2 s(blocking)를 **한 팔씩** 차례로. 그리고 lerobot-record 가 팔로워 쌍 → 리더 쌍 순서로 부른다.
- 바꾼 것(`parallel_arms.py` 두 패키지에 추가, `LEROBOT_PARALLEL_ARMS=0` 으로 끈다):
  1. `BiWidowXAIFollowerRobot` · `BiWidowXAILeaderRobot` 의 connect/configure/disconnect 를 **좌우 두 스레드로 동시에**(자세·goal_time 그대로, 한쪽 예외는 다른 쪽을 기다린 뒤 다시 올림).
  2. lerobot-record 경로에서 **리더 쌍을 팔로워와 동시에** — `make_teleoperator_from_config` 를 감싸 teleop 을 등록하고, `MobileAIRobot.connect/disconnect` 가 리더의 connect/disconnect 를 같은 시간에 스레드로 돌린다. record 의 `teleop.connect()` 는 이미 연결이면 건너뛰고, `teleop.disconnect()` 는 record 자신의 `is_connected` 가드로 건너뛴다. 로봇 연결이 실패하면(e-stop 등) 리더를 기다려 접은 뒤 예외. stage_runner 등 다른 진입점은 쌍 단위 동시만 적용.
  3. `eval_najy.sh`: 띄우기 전에 팔 4 대 TCP 50001 사전 확인(1 s, `SKIP_NETCHECK=1` 로 끔) — 유선 끊김이면 130 s 대기 대신 즉시 exit 4.
- 실측(사용자 시험, 빈손): **켜기 13 s → 9 s(양팔) → 6 s(네 팔)**, **끄기 18 s → 11 s → 5 s**. 네 팔 판 첫 실기 1142(재생)·1145 에서 리더가 두 번 움직이는 일 없음 — 연결·해제 로그 시각이 네 팔 같은 초. 남은 시간은 카메라 3 대 연결(≈3~4 s, 순차).
- 오프라인 시험: 가짜 팔로 동시 0.50 s / 끔 1.00 s, 예외 전파, 리더 connect 건너뜀·disconnect 뒤 is_connected False.
