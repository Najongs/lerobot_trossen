## 2. 지금까지 정해진 것 (학습·오프라인)

전부 시간순 홀드아웃, 실기 조건(베이스 state 칸을 정책 자신의 명령으로 채움) 채점. 주 지표는 이동 단계 `base_step_mae`, 조작 단계 팔 MAE.

| # | 결정 | 상태 | 근거 (sim 레포) |
|---|---|---|---|
| 1 | **정책은 ACT** (52M, chunk 30). SmolVLA 는 같은 서버·같은 데이터에서 같거나 진다 — 이동 4단계·11단계 모두. 추론도 18배 느리다(531 vs 28.7 ms) | 확정 | §74, S2-22·24 |
| 2 | **베이스 state 는 0 (「14D」)**. 바퀴 속도를 넣으면 처음 보는 에피소드에서 그 칸을 베껴 확실히 나빠진다. 누적 위치(odom)는 0 과 구분 안 됨 | 확정 (두 서버) | S2-15·16, §59.1 |
| 3 | **11단계를 모델 하나로** — 단계별 모델보다 같거나 낫다. 이득은 자기 에피소드가 적은 단계일수록 크다(이동 task01·10, 조작 task02 −60%) | 확정 | §83·§85, S2-18·26 |
| 4 | **학습 길이 120K** (11단계). 60K 에서 밀리던 task01·06 이 120K 에서 따라잡았다 | 확정 | §83 |
| 5 | **원핫은 배포 요건이지 성능 레버가 아니다** — 세 번 비교에서 이득 없음. 시간 기반 단계 전환이라 단계 번호를 이미 알아 넣는다 | 확정 | §74, S2-18·24 |
| 6 | **최대 레버는 그 단계 자신의 데이터 수** — 30→93ep 이 −0.0262. 다른 단계를 섞는 것은 모자랄 때만 대체재(task06 80ep 캡 인과 실험) | 확정 | §72·§80 |
| 7 | **외부 데이터(GIST·서드파티)를 섞으면 나빠진다** | 확정 | §65·§66 |
| 8 | **exec 는 오프라인으로 못 정한다** — 녹화 재생은 exec 5 를, 폐루프 근사는 exec 30 을 편든다 → 실기에서 정했다(아래 3절: **30**) | 실기로 확정 | §84, §87 |
| 9 | 시간 앙상블 기각 · 증강 효과 없음(표준 off) · LR 1e-5 와 3e-5 차이 없음 | 확정 | §77, §61 |

**채점에서 배운 것** — 에러 없이 틀린 숫자가 세 번 나왔다(정규화 누락 · 학습 에피소드로 채점 · 길이를 재던 기준선).
그래서 `base_step_mae` 로 바꿨고, 문턱은 **설정마다 시드폭으로 다시 잰다**(단일 태스크 0.007, 다단계 0.0101). 상세: sim §37·§53·§73.

**10/06 의 핵심 발견** — 11단계 모델은 **원핫보다 카메라 장면과 팔 시작 자세로 단계를 정한다**
(오프라인 교란: 카메라·팔 state 를 바꾸면 청크가 원핫 교환의 약 3배 변한다). task05 의 시작은 task04 의 끝과 장면·자세가 거의 같아서
M1 이 task04 를 이어 했다. 2호기 T5(2026-09-28)의 「정책은 영상에서 그 에피소드의 타이밍을 읽고 state 칸은 거의 안 쓴다」 와 같은 방향이다.

**오후 추가** — task03 에서 회전의 **출발이 cam_high 한 장에 걸려 있다**: 정지한 프레임에 cam_high 만 바꿔 넣으면 돌고, 팔 state·손목 카메라·원핫을 바꿔서는 안 돈다
(같은 장면·같은 원핫에서 3ep 중 1ep 만 출발). 원핫 문제와 별개로 「시작 관측이 조금 어긋나면 출발하지 않는다」 가 이동 단계의 두 번째 문제다.

**사람 결정(10/06)**: 원핫으로 단계를 고르는 것이 목표였으므로 「시작 자세로 단계를 맞추는」 우회는 채택하지 않는다.
task05 는 「11단계 모델 + 원핫으로는 안 됨」 으로 두고 **D(이동 단계)로 넘어간다.**

## 4. 다음 (순서)

1. **실기 D — 이동 단계**: task03 재시험(시작 자세를 허용 0.32 안으로 — 손목 j4 까지) `scripts/eval_najy.sh M1 3 30 3` → task01 재시험(**비커 선반 앞에서 시작**) → task06·10.
   **시작 장면(로봇 위치·방향·물체 위치)과 팔 자세를 시연 첫 프레임과 맞추는 것**이 핵심 — 10/06 의 task01 두 회차는 위치가, task03 세 에피소드는 자세가 어긋나 판정에 못 썼다.
   이동 단계 기준 회전·전진량은 21 Hz 환산값을 쓴다(task03 −81°, task01 +82°·1.64 m) — 10/06 task03 성공 회전이 실측 −85° [1ep]
2. **학습 쪽 대책 (DGX)** — 원핫이 단계를 실제로 고르게 만들기. 후보: 비슷한 장면의 단계(task04↔05)를 원핫만으로 가르도록 데이터·조건을 바꾸기.
   진단은 끝났다(10/06, sim 레포 §89): 인접 경계 10곳 중 9곳에서 원핫은 단계를 고르지 않는다(M1·M2 공통) → 대책은 일반적이어야 한다. 설계는 2호기 후속(T8 증강 대조·fps·장면 유사도) 결과 뒤.
   로봇 PC 가 10/06 오후에 넘긴 것(출발이 cam_high 에 걸림 · fps 는 20~21 Hz 쪽 · 대조쌍 1350 ep0 대 ep1·ep2): [`eval_najy_results_1006.md`](eval_najy_results_1006.md) 「1호기로 넘기는 것 — 오후 추가」
3. **데이터 수집 (사람 결정 대기)** — 최대 레버. 이동 task01·10·03, 조작 task02 가 가장 모자란다
4. 보류: C-3 (M2 task05) · exec 5 재시험(하지 않는다) · SmolVLA 추가 실험(하지 않는다)
5. **로봇 PC → DGX 전송 대기 (사람)**: 1006 회차 eval 데이터셋 6개(오후 1347_t01·1350_t03 포함)·로그. 녹화 teleop 루프 Hz(target 30 에서도 21.4 Hz)·task01 관찰·θ 부호는 답했다 — `eval_najy_results_1006.md` 「Trossen PC1 답」
